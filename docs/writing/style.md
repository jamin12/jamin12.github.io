# 본문 규약

마크다운 일반 문법은 적지 않는다. **이 블로그에서만 다른 것**과 **글을 쓰다가 정한 판단**만 모은다.

기본은 GitHub Flavored Markdown이고, 표·체크리스트·취소선은 그냥 된다. 아래는 그 밖의 것들이다.

---

## 헤딩은 `##`부터

`#`(h1)은 쓰지 않는다. 글 제목은 frontmatter `title`이고, 본문에 h1이 또 있으면 제목이 두 개가 된다.

목차에는 **h2와 h3만** 올라간다. h4 이하는 렌더링은 되지만 목차에서 빠지므로, 목차에 걸려야 하는 절은 h3까지로 맞춘다.

---

## 코드블록 — 지원 언어가 정해져 있다

`js` `ts` `jsx` `tsx` `html` `css` `json` `bash` `md` `yaml` `sql` `python` `go` `rust` `java` `kotlin`

**목록에 없는 언어는 하이라이팅 없이 plain text로 나온다.** 렌더가 깨지지는 않지만 색이 안 붙는다. 자주 쓸 언어가 생기면 `src/lib/shiki.ts`에 모듈 한 줄을 추가한다. 전부 넣지 않는 이유는 [`specs/rendering.md`](../specs/rendering.md#3-코드블록-하이라이팅) 참조.

---

LaTeX가 된다. 인라인 `$O(n \log n)$`, 블록 `$$ ... $$`.

## 다이어그램

` ```mermaid ` 코드블록이 다이어그램으로 렌더링된다.

- 라이트/다크에 맞춰 색이 자동으로 바뀐다. **색을 직접 지정하지 않는 편이 낫다**
- 문법 오류가 나면 에러 박스가 그대로 보인다. 조용히 빈칸이 되지 않는다
- mermaid 라이브러리는 무겁지만 다이어그램이 있는 글을 열 때만 로드된다. 다른 글에는 비용이 없다

## 이미지 경로

본문에서는 **항상 `./images/<파일>`** 로 쓴다. 다른 형태의 상대경로는 해석되지 않는다. 파일을 어디에 두는지는 [organizing.md](organizing.md#파일을-어디에-두나).

```markdown
![TCP 핸드셰이크](./images/tcp-handshake.png)
```

- `https://`로 시작하는 외부 URL은 그대로 통과
- 경로가 틀리면 **404가 그대로 보인다.** 오타를 놓치지 않게 일부러 그렇게 뒀다
- 다른 카테고리의 이미지는 참조할 수 없다. 두 글에 같은 이미지가 필요하면 각 카테고리 `images/`에 하나씩

## 내부 링크는 `/`로 시작

| 대상 | 쓰는 법 |
|------|--------|
| 블로그 안 다른 글 | `[제목](/posts/<slug>)` |
| 카테고리·태그 | `[제목](/categories/<카테고리>)`, `[제목](/tags/<태그>)` |

전체 URL(`https://...`)을 적으면 외부 링크로 처리돼 새 탭이 열린다. `/`로 시작해야 새로고침 없이 이동한다.

## 문체

### 괄호 병기를 쓰지 않는다

`설명(파라미터명)` 식으로 용어 뒤에 괄호를 붙여 원어나 식별자를 병기하지 않는다.

```markdown
# 안 좋음
전송 대기 중인 레코드를 담는 버퍼(RecordAccumulator)에 쌓인다.
최대 대기 시간(linger.ms) 동안 기다린다.

# 좋음
전송 대기 중인 레코드는 RecordAccumulator에 쌓인다.
linger.ms 만큼 기다린다.
```

**왜**: 괄호가 한 문단에 두세 개 붙으면 읽는 흐름이 계속 끊긴다. 대부분 둘 중 하나만 있어도 뜻이 통한다 — 식별자가 중요하면 식별자를 본문에 그대로 쓰고, 개념이 중요하면 개념만 쓴다. 둘 다 필요한 건 그 용어를 처음 소개하는 한 곳뿐이다.
